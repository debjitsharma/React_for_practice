1) What is another way of starting the build of the project?
   
   We will be creating scripts instead of using “npx parcel index.html”. We can create different scripts for starting our
   project in Development and Production.

   In package.json , in the script section write the following command.

   
  "scripts": {
    "test": "jest",
    "start": "parcel index.html",          ( We can give any name instead of start and build.This depends on us.)
    "build": "parcel build index.html"

  }

  To run these scripts, enter the following commands in the terminal,
  a) To start: npm run start
     or npm start            ( start and test. Those two are special because npm lets you run them without the word run)
  
  b) For Production Build: npm run build

    If you’re not sure how to start the project in a new company then find these scripts in package.json and use them.

2) What is JSX?
   JSX is HTML like or XML like syntax. JSX stands for Javascript XML. It's a syntax extension for Javascript.

   It's not a part of React. React apps can be built even without JSX but the code will become very hard to read.

   It's not HTML inside JavaScript.

   JavaScript engine cannot understand JSX as it only understands ECMAScript.

   //Using Pure React
   const heading=React.createElement("h1",{id;"heading"},"Namaste Javascript");

   //using JSX
   const jsxHeading= <h1>Namaste React using Javascript<h1>

   When we log heading and jsxHeading in the console, it gives the same object.
   
3) Is JSX a valid JavaScript?
   
   The answer is yes and no.

  JSX is not a valid Javascript syntax as it’s not pure HTML or pure JavaScript for a browser to understand. JS does not have
  built-in JSX. The JS engine does not understand JSX because the JS engine understands ECMAScript or ES6+ code.


4) If the browser can’t understand JSX how is it still working?
   
  This is because of Parcel because “Parcel is a Beast”.  Before the code gets to JS Engine it is sent to Parcel and 
  Transpiled there. Then after transpilation, the browser gets the code that it can understand.

  Transpilation ⇒ Converting the code in such a format that the browsers can understand.

 Parcel is like a manager who gives the responsibility of transpilation to a package called Babel.
 
 Babel is a package that is a compiler/transpiler of JavaScript that is already present inside ‘node-modules’. 
 It takes JSX and converts it into the code that browsers understand, as soon as 
 we write it and save the file. It was not created by Facebook.

 JSX (transpiled by Babel) ⇒ React.createElement ⇒ReactElement ⇒ JS Object ⇒ HTML Element(render)


5) What is the difference between HTML and JSX?
   
  JSX is not HTML. It’s HTML-like syntax.

  HTML uses ‘class’ property whereas JSX uses ‘className’ property.

  HTML can use hypens in property names whereas JSX uses camelCase syntax.

  a)lowerCamelCase – starts with a lowercase letter (used for variables, functions)
  → totalPrice, handleClickEvent

  b)UpperCamelCase (PascalCase) – starts with an uppercase letter (used for classes, components)
  → UserProfile, PaymentGateway

 6) Single Line and Multi Line JSX Code
    
    a) Single line code: const jsxHeading = <h1>Namaste React</h1>

    b) Multi-line code: If writing JSX in multiple lines then using ‘()’ parenthesis is mandatory. To tell Babel from where JSX is starting and ending.
        const jsxHeading = (
                            <div>
                            <h1>Namaste React</h1>
                            </div>
                            )
                              
7) What are Components?

  A component is just a JavaScript function (or class) that returns a piece of UI — usually written in JSX — which React then turns into actual DOM elements on the page.

   There are 2 types of components:
   1.Class-based Components - Old way of writing code, used rarely in industry.
   2.Functional Components - New way of writing code, most commonly used in industry.

8) What is a React Functional Components?
   
  It is just a JavaScript Function that returns some JSX or a react element.

  Always name React Functional Component with Capital Letters otherwise you will confuse it with normal function. (Also functional component will not be recognised and rendered. Personal experience.)

  //All are the same for single-line code

   const HeadingComponent1 = () => (
    <h1>Debjit</h1>
   )

   const headingComponent2 = () => {
    return <h1>Debjit</h1>
   }

   const HeadingComponent3 = () => <h1> Debjit </h1>

  To render a functional component we call them ‘<Heading1 />’. This is the syntax that Babel understands. 
  You can also call them using, <Title></Title>’ 


9) Components Composition
  
   A component inside a component.
   Calling a component inside another component is Component Composition.

  const Title = () => <h1>Namaste React</h1>
  const HeadingComponent = () => (
  <div id="container">
  <Title />
  </div>
  )

  It will become something like this,

  const HeadingComponent = () => (
  <div id="container">
  <h1>Namaste React</h1>
  </div>
  )

  Without div it will show an error.
  const Heading = () => (<parent/> <h1>This is me Function Componenet</h1>);
  
  The problem is that JSX can only return one parent element. 
  You’re trying to return two separate siblings — <parent/> and <h1>...</h1> — side by side, and JSX doesn’t tolerate that without a wrapper.

  const Heading = () => (
  <>
    <parent />
    <h1>This is me Function Component</h1>
  </>
  );
  This is also valid.


10) How to use JavaScript code inside JSX?
    
    Inside a React Component when ‘{}’ parenthesis is present we can write any JavaScript expression inside it.

    const number = 10000;
    const HeadingComponent = () => (
    <div id="containter">
    {number}
    <h1>Namaste React</h1>
    </div>
    )
